# 四模板端到端回归报告

- 环境：本地 Vite 开发服务

## 2. 测试目标

本轮不是只检查页面能否打开，而是模拟用户反复编辑活动时的实际操作：

1. 分别进入四套模板。
2. 修改中文、英文、数字、长文案、短文案和空值。
3. 增加、删除、清空字段和段落。
4. 在蓝图表格与正式预览之间往返。
5. 切换同一模块的不同业务状态。
6. 检查第一步编辑数据是否正确传到第二步预览。
7. 在预览中继续编辑，再返回蓝图检查是否回写。
8. 进入导出切图页，核对文案、状态和编辑态 UI。
9. 对发现的问题直接修改代码，再重复原步骤回归。

## 3. 模板 1：只发券

### 3.1 测试内容

- 修改普通头图标题，覆盖中文、英文、数字和长短文案。
- 清空头图日期，检查蓝图预览、正式预览和导出页。
- 将“用户教育｜投放攻略”从四段逐步减少到一段。
- 检查段落减少时，正文、分隔线、按钮和白色外框是否同步上移。
- 再增加文案，检查组件是否能重新增高。
- 从蓝图进入预览，再返回蓝图，检查字段是否保持。
- 进入导出页，核对头图、发券、内容诊断、投放攻略等模块。

### 3.2 发现的问题

1. 普通头图日期在蓝图中可以清空，但进入正式预览后重新显示默认日期 `6月10日-6月21日`。
2. 根因不是头图 React 组件本身，而是正式预览重建节点时跳过了空字符串，导致 schema 默认值重新生效。
3. 此问题不仅影响日期，理论上所有允许清空的普通模板文字字段都可能出现“蓝图为空、正式预览恢复默认值”。

### 3.3 修改内容

- 将头图日期兜底从逻辑或 `||` 改为 null 合并 `??`，使空字符串被视为合法用户输入。
- 修改模板变量写入正式预览节点的逻辑：只要存在模板变量行，即使值为空，也写入节点。
- 保留 `null` 和 `undefined` 的兜底行为，不影响真正没有配置过的字段。
- 投放攻略组件由固定高度改为内容驱动的最小高度，移除阻止组件缩短的固定高度约束。

### 3.4 回归结果

- 蓝图日期清空后，蓝图头图不显示日期：通过。
- 进入正式预览后日期仍为空：通过。
- 导出页“背景+头图”和“头图”切图预览均不显示日期：通过。
- 投放攻略四段减少到一段时，高度约从 669px 缩至 424px：通过。
- 文案重新增加时，组件重新增高：通过。

## 5. 模板 3：抽奖 + 消耗返

### 5.1 测试内容

- Big-day 发券在“报名前”和“已报名”之间反复切换。
- 两个状态分别输入不同文字，再往返检查是否互相覆盖。
- 四档消耗返的第四档输入门槛 `4444`、券金额 `8888`。
- 执行“四档 → 三档 → 正式预览 → 蓝图 → 四档”。
- 检查三档状态是否隐藏第四档，切回四档后数据是否恢复。
- 检查正式预览中的档位数量和文案。

### 5.2 发现的问题

- 原逻辑在用户切换到三档时，主动将第四档相关字段写为空字符串。
- 因此切回四档后，第四档只能恢复默认值或空值，用户输入永久丢失。

### 5.3 修改内容

- 删除“三档状态下清空第四档字段”的逻辑。
- 三档状态现在只控制第四档是否展示，不再修改第四档的数据。
- 切回四档时直接使用之前保存的数据。

### 5.4 回归结果

- 三档正式预览中不显示 `4444/8888` 和第四档：通过。
- 返回蓝图后，隐藏状态下第四档数据仍为 `4444/8888`：通过。
- 切回四档后蓝图重新显示 `4444/8888`：通过。
- 再进入正式预览后第四档也显示 `4444/8888`：通过。
- Big-day 报名前和已报名字段独立保存：通过。

## 6. 模板 4：无激励攻略

### 6.1 测试内容

- 切换“入口卡片、优质视频提示、账号问题提示”。
- 在入口卡片内继续切换“点击前、点击后”。
- 分别输入：
  - 点击前：`入口前独立A123`
  - 点击后：`入口后独立B456`
  - 优质视频提示：`优质独立C789`
- 执行多次状态切换。
- 进入正式预览，再返回蓝图继续检查。

### 6.2 发现的问题

- 入口卡片标题与优质视频提示标题共用了同一条基础变量记录。
- 在某个状态修改标题后，切换到另一个状态会看到刚才的内容，属于状态串写。
- 点击前和点击后虽然组件不同，但状态数据没有使用独立存储标识。

### 6.3 修改内容

- 为模板 4 内容诊断状态建立独立状态存储 ID。
- 入口点击前使用 `entry:default`。
- 入口点击后使用 `entry:clicked`。
- 优质视频和账号问题提示继续使用各自业务状态 ID。
- 切换状态时，根据目标 schema 默认值初始化一次，之后读取该状态自己保存的数据。
- 重建入口状态节点时恢复对应状态的详情变量。
- 正式预览应用状态变量时支持复合状态 ID，避免覆盖其他状态。

### 6.4 回归结果

- 点击前始终保持 `入口前独立A123`：通过。
- 点击后始终保持 `入口后独立B456`：通过。
- 优质视频始终保持 `优质独立C789`：通过。
- 蓝图 → 正式预览 → 蓝图后，三组数据仍独立：通过。
