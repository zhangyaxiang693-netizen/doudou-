# 历史记录上线前检查

检查范围：个人/公共组保存、覆盖、复制、刷新、删除、快照恢复，以及关联登录会话配置。
已修改本地代码；没有推送、部署或执行远端数据库操作。

## 确认并修复的问题

| 问题 | 原来的影响 | 修复 |
| --- | --- | --- |
| 协作保存用定时器异步上传 | 界面提前显示成功，失败只写控制台 | 等待云端确认；失败显示错误并保留编辑内容供重试 |
| 修改时上传全量缓存 | 保存一条记录可能覆盖别人更新的其他记录 | 只上传修改项；已有记录/组携带打开时的更新时间，数据库检查冲突 |
| 新建组项目分两次保存 | 项目先进入个人区，随后移组失败可能留下错误归属 | 项目、快照、目标组在同一个事务提交 |
| 协作记录与项目快照分开更新 | 共享成员修改后，所有者打开的内容可能仍然是旧版；失败可能只写入一半 | 统一事务更新两处；覆盖保留原版本 ID |
| 软删除没清理协作记录 | 删除后仍能从协作列表看到，旧缓存可能再次上传 | 删除触发器清理关联记录；拒绝重建已删除项目的关联记录 |
| 恢复旧快照仅赋值已有字段 | 上一个项目的子状态、头图草稿或资源位选择残留 | 缺失字段补独立默认值；清理临时 UI 选择 |
| 所有账号共用浏览器缓存 | 账号切换可能带入其他账号/管理员缓存；缓存满可能打断流程 | 按用户隔离，限制缓存个人数据范围，容错浏览器存储失败 |
| 复制只改列表名称 | 打开副本后活动名称仍为原名称 | 同步更新副本快照内的活动名，保留原稿 |
| 生产 HTTPS 代理未声明信任 | HTTPS 在代理层终止时可能无法设置 secure 登录 Cookie | 配置可信代理跳数，并验证 secure Cookie；移除授权码和完整 token 响应日志 |

## 验证结果

- 47 项 Node 测试通过，包含原有主题恢复、头图文案规则和新回归用例。
- 在独立 PGlite PostgreSQL 中执行历史、协作、新增一致性迁移；
  验证目标组原子创建、公共组成员覆盖、旧缓存冲突、故障回滚、
  删除后重传、个人权限、批量事务回滚、版本 ID 保持及数据库 RPC 权限。
- Chromium 浏览器运行生产构建，使用拦截的模拟 API：
  云端响应前显示“保存中”，失败显示“保存失败”，重试保留名称，
  成功后刷新可见新记录，云端删除后刷新不再显示，保存只发送修改项；
  无页面运行时错误。
- Vite 生产构建通过；`git diff --check` 通过。

## 上线顺序与验证边界

1. 在目标环境数据库先执行
   `supabase/migrations/202610250001_history_consistency.sql`。
   开发库与生产库分别处理；部署前备份数据库。
2. 部署同一批前端和后端代码，刷新旧标签页。
3. 核对 `PROJECT_HISTORY_AUTH_ADAPTER`、稳定的 `SESSION_SECRET`、
   OAuth 回调域名、sessions 表及 `TRUST_PROXY_HOPS`。
4. 使用两个测试账号完成真实飞书登录、个人保存、公共组交叉编辑冲突、
   删除及重新登录恢复的线上验收。

本轮没有使用真实飞书 OAuth 或线上数据库验证；数据库验证与浏览器验证均在隔离环境完成。
因此本地验证通过不代替目标环境的迁移和登录验收。

旧共享缓存不自动导入，避免混入别人的数据。仅存在于旧浏览器、尚未同步到云端的内容，
需在旧页面打开后另存，再更新页面。原有云端项目不受缓存隔离影响。

接口及测试运行方式见 [project-history-contract.md](project-history-contract.md)。
